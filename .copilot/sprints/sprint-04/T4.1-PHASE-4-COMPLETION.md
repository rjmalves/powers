## Technical Implementation

### API Choice: Factory Pattern (from_files)

**Decision**: Use `SddpAlgorithm::from_files()` → `SddpInstance`

**Rationale**:
- Mirrors real-world usage (users load JSON files)
- Simplest approach for realistic benchmarks
- `SddpInstance` has `.train()` and `.simulate()` methods
- No need to manually manage SAA or configuration

**Alternative Considered**: Builder API (like existing benchmarks)
- **Rejected**: Requires manual system construction
- **Rejected**: Doesn't represent real usage patterns
- **Rejected**: More complex for loading examples

### Benchmark Design Principles

1. **Realistic Problem Sizes**
   - Example 04: Medium complexity (5 hydros, 24 stages)
   - Example 05: Production scale (156 hydros, 60 stages)

2. **Proper Warmup**
   - Cold start benchmarks: Measure first iteration overhead
   - Warm benchmarks: Pre-train (3-5 iterations) for steady-state

3. **Appropriate Sample Sizes**
   - CASCADE: 20 samples, 20s measurement time
   - LARGE-SCALE: 10 samples, 40s measurement time (more expensive)
   - Full training: 5 samples, 60s measurement time (very expensive)

4. **Black-Box Protection**
   - All benchmark closures use `black_box()` to prevent optimization
   - Results properly consumed to avoid dead code elimination

5. **Clear Naming**
   - Descriptive benchmark names indicate system and scenario
   - Grouped logically by operation type
