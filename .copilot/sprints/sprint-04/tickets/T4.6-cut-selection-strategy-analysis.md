## Technical Notes

### Cut Selection Strategies

**1. Level-Based Selection**:

- Select cuts by value level in dual space
- Pros: Fast, simple, good for linear problems
- Cons: May miss important cuts in non-linear regions
- Use when: Problem is mostly linear, need speed

**2. Dominance-Based Selection**:

- Select non-dominated cuts only
- Pros: High quality, removes redundant cuts
- Cons: Slower dominance check, complex
- Use when: Need high quality, have time budget

**3. Age-Based Selection**:

- Prioritize recently added cuts
- Pros: Fast, good cache locality
- Cons: May neglect older but important cuts
- Use when: Problem characteristics change over time

**4. Active Set Management**:

- Activate/deactivate cuts dynamically
- Pros: Memory efficient, faster LP solves
- Cons: Overhead of activation logic
- Use when: Many cuts, memory constrained

### Benchmark Structure

```rust
use criterion::{black_box, criterion_group, criterion_main, Criterion, BenchmarkId};

fn cut_selection_strategy_benchmark(c: &mut Criterion) {
    let mut group = c.benchmark_group("cut_selection_strategies");

    for strategy in ["level", "dominance", "age", "active_set"].iter() {
        for problem in ["thermal", "hydrothermal", "complex"].iter() {
            group.bench_with_input(
                BenchmarkId::new(*strategy, *problem),
                &(strategy, problem),
                |b, &(strat, prob)| {
                    let mut sddp = create_problem_with_strategy(prob, strat);
                    b.iter(|| {
                        black_box(sddp.train_iteration())
                    });
                },
            );
        }
    }

    group.finish();
}
```

### Strategy Recommendations

Document decision tree like:

```
Problem Characteristics:
├─ Many cuts (>500)?
│  ├─ Yes → Use active set management (memory efficiency)
│  └─ No → Continue
├─ Need highest quality?
│  ├─ Yes → Use dominance-based (best quality, slower)
│  └─ No → Continue
├─ Need speed?
│  ├─ Yes → Use level-based (fastest)
│  └─ No → Use age-based (balanced)
```

### Expected Results

Based on typical SDDP behavior:

- **Level-based**: Fastest iteration, good convergence for most problems
- **Dominance-based**: Slowest iteration, best solution quality, fewer total cuts
- **Age-based**: Medium speed, good for non-stationary problems
- **Active set**: Best memory usage, medium speed, good for large problems
