## Context

Production-quality libraries need excellent error messages that help users understand what went wrong and how to fix it. This ticket audits and improves error messages throughout the codebase.

**Why This Matters**:

- Users should never see cryptic error messages
- Error messages should suggest solutions
- Good errors reduce support burden
- Demonstrates polish and quality

**Current State**:

- Some error messages are technical/cryptic
- Not all errors suggest solutions
- Error context sometimes missing
- No consistent error message style

**Target State**:

- All errors have clear, user-friendly messages
- Errors include context (what operation failed, why)
- Errors suggest solutions when possible
- Consistent error message style

## Technical Notes

### Error Message Style Guide

**Format**:

```
Failed to <action>: <reason>. <suggestion>.
```

**Good Examples**:

```
❌ Bad:  "Invalid input"
✅ Good: "Failed to parse system configuration: generator 'hydro1' has negative capacity (-50.0). Capacity must be non-negative. Check 'system.json' line 15."

❌ Bad:  "Infeasible"
✅ Good: "Subproblem infeasible at stage 3. The demand (500 MW) exceeds total generation capacity (400 MW). Increase capacity or reduce demand. See docs/guides/TROUBLESHOOTING.md#infeasible-problems."

❌ Bad:  "File error"
✅ Good: "Failed to read scenario file: 'scenarios.json' not found in current directory. Check that the file exists and the path is correct."
```

**Context to Include**:

- What operation was being performed
- What value caused the problem
- Where the problem occurred (file, line, stage, scenario)

**Suggestions to Include**:

- How to fix the immediate problem
- Where to find more information (docs link)
- Who to contact if it's a bug

### Error Type Categories

1. **Input Validation**: User provided invalid data

   - Include: Invalid value, valid range, location
   - Suggest: Correct value, check documentation

2. **File I/O**: Can't read/write file

   - Include: File path, operation (read/write)
   - Suggest: Check path, check permissions, check format

3. **Configuration**: Invalid settings

   - Include: Setting name, invalid value, valid range
   - Suggest: Correct value, check documentation

4. **Runtime**: Problem during execution

   - Include: Operation, stage/scenario, diagnostic info
   - Suggest: Check problem setup, report bug if unexpected

5. **Solver**: LP solver issue
   - Include: Problem type (infeasible/unbounded), stage/scenario
   - Suggest: Check constraints, check data, increase capacity

### Implementing Good Errors

**Use `thiserror` for custom errors**:

```rust
use thiserror::Error;

#[derive(Error, Debug)]
pub enum PowersError {
    #[error("Failed to parse {file}: {source}")]
    ParseError {
        file: String,
        source: serde_json::Error,
    },

    #[error("Invalid generator capacity: {name} has capacity {capacity}, must be non-negative. Check {file}")]
    InvalidCapacity {
        name: String,
        capacity: f64,
        file: String,
    },

    #[error("Subproblem infeasible at stage {stage}. Demand ({demand} MW) exceeds capacity ({capacity} MW). Increase capacity or reduce demand. See docs/guides/TROUBLESHOOTING.md#infeasible")]
    InfeasibleSubproblem {
        stage: usize,
        demand: f64,
        capacity: f64,
    },
}
```

**Add context with `anyhow`**:

```rust
use anyhow::Context;

fn load_system(path: &str) -> Result<System> {
    let content = std::fs::read_to_string(path)
        .with_context(|| format!("Failed to read system file: '{}'. Check that file exists", path))?;

    let system: System = serde_json::from_str(&content)
        .with_context(|| format!("Failed to parse system file: '{}'. Check JSON format", path))?;

    Ok(system)
}
```

**Include context in panic messages**:

```rust
// ❌ Bad
assert!(capacity > 0.0);

// ✅ Good
assert!(
    capacity > 0.0,
    "Generator '{}' has invalid capacity {}, must be positive",
    name, capacity
);
```

### Common Error Patterns

**File not found**:

```rust
return Err(anyhow!(
    "Failed to read {}: file not found. Check that '{}' exists in current directory",
    file_type, path
));
```

**Invalid value**:

```rust
return Err(anyhow!(
    "Invalid {}: {} = {}, must be {}. Check '{}' line {}",
    field_name, field_name, value, constraint, file, line
));
```

**Infeasible problem**:

```rust
return Err(anyhow!(
    "Subproblem infeasible at stage {}. {}. See docs/guides/TROUBLESHOOTING.md#infeasible",
    stage, diagnosis
));
```

**Internal error**:

```rust
return Err(anyhow!(
    "Internal error: {}. This may be a bug. Please report at {}",
    description, ISSUE_URL
));
```

### Testing Error Messages

```rust
#[test]
fn test_error_message_includes_context() {
    let config = Config {
        generators: vec![
            Generator { capacity: -100.0, ..Default::default() }
        ],
    };

    let result = System::from_config(&config);

    assert!(result.is_err());
    let err = result.unwrap_err().to_string();

    // Check error message is helpful
    assert!(err.contains("capacity"));
    assert!(err.contains("-100.0"));
    assert!(err.contains("non-negative"));
}
```

### Common Patterns

**Good error context**:

```rust
use anyhow::{Context, Result};

fn process_file(path: &str) -> Result<Data> {
    let data = read_file(path)
        .with_context(|| format!("Failed to read '{}'. Check file exists", path))?;

    parse_data(&data)
        .with_context(|| format!("Failed to parse '{}'. Check JSON format", path))?
}
```

**Error with suggestion**:

```rust
if capacity < 0.0 {
    bail!(
        "Invalid capacity for generator '{}': {} (must be non-negative). Check 'system.json'",
        name, capacity
    );
}
```
