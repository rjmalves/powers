## Technical Notes

### Parallel Efficiency Metrics

**Speedup**:

```
S(p) = T(1) / T(p)
```

where T(1) is single-thread time, T(p) is p-thread time

**Parallel Efficiency**:

```
E(p) = S(p) / p = T(1) / (p × T(p))
```

Target: E(p) ≥ 0.8 (80% efficiency)

**Amdahl's Law** (theoretical limit):

```
S(p) ≤ 1 / (f_serial + f_parallel / p)
```

where f_serial + f_parallel = 1

### Benchmark Structure

```rust
use criterion::{black_box, criterion_group, criterion_main, Criterion, BenchmarkId};
use rayon::prelude::*;

fn parallel_efficiency_benchmark(c: &mut Criterion) {
    let mut group = c.benchmark_group("parallel_efficiency");

    for threads in [1, 2, 4, 8].iter() {
        group.bench_with_input(
            BenchmarkId::new("forward_pass", threads),
            threads,
            |b, &threads| {
                rayon::ThreadPoolBuilder::new()
                    .num_threads(threads)
                    .build_global()
                    .unwrap();

                let (mut sddp, saa) = create_benchmark_problem();

                b.iter(|| {
                    black_box(sddp.forward_pass(black_box(&saa.scenarios)))
                });
            },
        );
    }

    group.finish();
}
```

### Plotting Scaling Curves

```python

import numpy as np
```

### Expected Findings

Based on typical SDDP parallelization:

- **Forward pass**: 80%+ efficiency up to 16-32 threads (scenario-level parallelism)
- **Backward pass**: 60-80% efficiency (more synchronization due to cut sharing)
- **Bottlenecks**: Scenario generation (serial), cut addition (synchronization)

### Optimization Opportunities

High-priority candidates:

1. **Reduce cut addition synchronization**: Batch cuts before adding to solver
2. **Improve load balancing**: Sort scenarios by complexity
3. **Optimize scenario generation**: Parallelize if possible
4. **Use work stealing**: Rayon already does this, but tune chunk size

### Thread Tuning Recommendations

Document guidelines like:

- **Small problems** (<100 scenarios): Use 4-8 threads
- **Medium problems** (100-1000 scenarios): Use 8-16 threads
- **Large problems** (>1000 scenarios): Use 16-32 threads
- **Hyperthreading**: Generally use physical cores only
- **NUMA systems**: Be aware of memory locality

Formula:

```
optimal_threads = min(
    physical_cores,
    num_scenarios / 10,  # At least 10 scenarios per thread
    32                   # Diminishing returns beyond 32
)
```

### Amdahl's Law Analysis

Calculate serial fraction:

```
Given: S(8) = 6.5 (measured 6.5× speedup with 8 threads)

Using Amdahl's law:
S(p) = 1 / (f_serial + f_parallel / p)
6.5 = 1 / (f_serial + (1 - f_serial) / 8)

Solving: f_serial ≈ 0.03 (3% serial)

Theoretical limit: S(∞) = 1 / 0.03 ≈ 33×
```
