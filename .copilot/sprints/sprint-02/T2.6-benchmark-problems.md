## Technical Implementation

### Benchmark 1: Deterministic Single Reservoir (Exact Solution)

**Problem Formulation**:

- **System**: 1 bus, 1 hydro reservoir, 1 thermal plant
- **Time**: 2 stages (t=0, t=1)
- **State**: Reservoir storage $s_t$ (e.g., initial $s_0 = 50$ MWh)
- **Inflows**: Deterministic (e.g., $i_0 = 20$, $i_1 = 30$ MWh)
- **Demand**: Fixed (e.g., $d = 60$ MWh per stage)
- **Costs**: Thermal cost $c_{thermal} = 10$ \$/MWh, hydro cost = 0

**Decision Variables**:

- $g_t^{hydro}$: Hydro generation at time $t$
- $g_t^{thermal}$: Thermal generation at time $t$
- $s_t$: Storage at end of time $t$

**Constraints**:

```
Generation: g_t^hydro + g_t^thermal >= d
Hydro limits: 0 <= g_t^hydro <= min(turbine_max, storage + inflow)
Thermal limits: 0 <= g_t^thermal <= thermal_max
Storage dynamics: s_t = s_{t-1} + i_t - g_t^hydro - spillage_t
Storage bounds: s_min <= s_t <= s_max
```

**Optimal Solution** (Analytical):

- Use hydro to maximum extent (cheaper than thermal)
- Only use thermal when hydro insufficient
- For parameters above: Total cost ≈ $100-200 (mostly thermal in stage where hydro depleted)

**SDDP Should**:

- Converge to exact solution (gap < $0.10)
- Show policy: $g^{hydro}$ = max available, $g^{thermal}$ = remainder

```rust
// tests/fixtures/benchmarks.rs

pub fn create_deterministic_single_reservoir() -> HydrothermalBenchmark {

        10,    // training iterations
        5,     // forward scenarios
        42,    // seed
    );

    // SAA: Single scenario (deterministic)
    let saa = create_deterministic_saa(&deterministic_inflows);

    // Expected solution (can compute exactly)

        optimal_value: Some(compute_deterministic_solution(&system, &deterministic_inflows)),
        lower_bound: 0.0,
        upper_bound: 1000.0,  // Upper bound from feasible solution
        tolerance: 0.10,       // Very tight (deterministic)
        reference: Some("Analytical solution".to_string()),
        policy_characteristics: vec![
            "Use hydro before thermal".to_string(),
            "Deplete hydro in later stages".to_string(),
            "Zero spillage (valuable water)".to_string(),
        ],
    };

    HydrothermalBenchmark {
        name: "Deterministic Single Reservoir".to_string(),
        system,
        config,
        saa,
        expected_solution: expected,
        description: "Simplest hydrothermal problem with exact solution".to_string(),
    }
}

fn compute_deterministic_solution(system: &System, inflows: &[f64]) -> f64 {
    // Simple DP or LP solution
    // For demonstration: water_value * unused_water + thermal_cost * thermal_gen
    // This can be computed analytically for 2-stage problem

    let initial_storage = 50.0;
    let demand = 60.0;
    let thermal_cost = 10.0;
    let hydro_capacity = 40.0;

    let mut total_cost = 0.0;
    let mut storage = initial_storage;

    for (t, inflow) in inflows.iter().enumerate() {
        let available_hydro = (storage + inflow).min(hydro_capacity);
        let hydro_gen = available_hydro.min(demand);
        let thermal_gen = (demand - hydro_gen).max(0.0);

        total_cost += thermal_gen * thermal_cost;
        storage = storage + inflow - hydro_gen;

        // Final stage: penalize leftover water (opportunity cost)
        if t == inflows.len() - 1 {
            // Water value ~ 0 for final stage (no future use)
        }
    }

    total_cost
}
```

### Benchmark 2: Stochastic Single Reservoir (3 Scenarios)

**Problem Formulation**:

- **System**: Same as Benchmark 1
- **Stage 1**: Deterministic inflow $i_0 = 20$ MWh
- **Stage 2**: Stochastic inflow $i_1 \in \{10, 30, 50\}$ MWh with probabilities $\{0.25, 0.50, 0.25\}$

**Challenge**: Stage 1 decision must hedge against stage 2 uncertainty

**Optimal Policy Characteristics**:

- Stage 1: Save some water (don't deplete completely) to hedge against low inflow
- Expected cost higher than deterministic average (cost of hedging)
- Converges to DP solution for small state space

**DP Solution** (Computable):

- State space: Storage levels $s \in [0, 100]$ (discretize)
- Bellman equation: $V_t(s) = \min_{g^h, g^{th}} \{ c \cdot g^{th} + E[V_{t+1}(s')] \}$
- Can solve with value iteration (2 stages, small state space)

```rust

    }
}
```

### Benchmark 3: Two Reservoir Cascade

**Problem Formulation**:

- **System**: 1 bus, 2 hydro reservoirs (upstream → downstream), 1 thermal
- **Cascade**: Upstream turbining becomes downstream inflow
- **Inflows**: Independent for each reservoir (can be deterministic first)
- **Challenge**: Coordinate cascade to minimize total cost

**Water Balance**:

```
Upstream: s1_t = s1_{t-1} + i1_t - g1_t - spill1_t
Downstream: s2_t = s2_{t-1} + i2_t + (g1_t + spill1_t) - g2_t - spill2_t
```

**Optimal Policy**:

- Coordinate releases to avoid spillage
- Balance upstream storage value vs downstream generation opportunity
- More complex state space (2D)

```rust
pub fn create_two_reservoir_cascade() -> HydrothermalBenchmark {
    let mut system = System::new();

    let bus = Bus::new(0, 50.0);  // Deficit cost
    system.add_bus(bus);

    // Upstream reservoir
    let hydro_upstream = Hydro::new(
        0,           // id
        None,        // no upstream (this is top)
        0,           // bus_id
        1.0,         // productivity
        0.0, 100.0,  // storage bounds
        0.0, 40.0,   // turbining bounds
        0.01,        // spillage penalty
    );
    system.add_hydro(hydro_upstream);

    // Downstream reservoir (receives upstream outflow)
    let hydro_downstream = Hydro::new(
        1,              // id
        Some(0),        // downstream of hydro 0
        0,              // bus_id
        1.0,            // productivity
        0.0, 100.0,     // storage bounds
        0.0, 40.0,      // turbining bounds
        0.01,           // spillage penalty
    );
    system.add_hydro(hydro_downstream);

    // Thermal backup
    let thermal = Thermal::new(0, 0, 10.0, 0.0, 30.0);
    system.add_thermal(thermal);

    // ... rest of benchmark setup

    let expected = BenchmarkSolution {
        optimal_value: None,
        lower_bound: 0.0,
        upper_bound: 500.0,
        tolerance: 10.0,
        reference: Some("2D DP solution or literature reference".to_string()),
        policy_characteristics: vec![
            "Coordinate cascade releases".to_string(),
            "Minimize spillage at both reservoirs".to_string(),
            "Use downstream hydro efficiently".to_string(),
        ],
    };

    HydrothermalBenchmark {
        name: "Two Reservoir Cascade".to_string(),
        system,
        config: create_simple_config(2, 30, 10, 42),
        saa,
```

## Notes

**Why Hydrothermal Focus?**

POWE.RS is specifically designed for hydrothermal dispatch. Using domain-specific benchmarks:

1. **Validates domain logic**: Cascading, water balance, storage dynamics
2. **Tests realistic constraints**: Hydro productivity, thermal costs, spillage penalties
3. **Demonstrates real use cases**: What users will actually do with the tool
4. **Enables domain validation**: Experts can verify results make sense

**Generic benchmarks (newsvendor, inventory) don't test hydrothermal-specific code paths.**

**Benchmark Complexity**:

Start simple (deterministic, single reservoir) and increase complexity (stochastic, cascade). This allows:

- Quick validation during development
- Progressive testing of features
- Clear identification of where bugs occur

**Tolerance Selection**:

- Deterministic: Tight (< $0.10)
- Stochastic (3-5 scenarios): Medium (< $5.00)
- Stochastic (many scenarios): Looser (< $10.00)

Tolerances depend on problem scale and stochasticity.

- Hydro: free ($0)
- Thermal: $c_t \cdot t_t$ (expensive)

**Objective**: Minimize expected thermal cost

**Known Solution**: For small problems, can solve exactly via DP.

```rust
pub fn create_hydro_benchmark() -> (System, Config, SAA, BenchmarkSolution) {
    // Simple 2-stage hydro problem
    // Initial volume: 50, max volume: 100, demand: 40
    // Inflow ~ Uniform(20, 60)
    // Thermal cost: $10/unit

    // System setup (simplified - actual implementation more complex)
    let mut system = System::new();

    // Stage 1
    let stage1 = Stage::new()
        .with_state("reservoir_level", 0.0, 100.0, 50.0)  // Initial 50
        .with_decision("hydro", 0.0, 100.0)
        .with_decision("thermal", 0.0, 100.0)
        .with_cost(|decisions| 10.0 * decisions[1])  // Thermal cost
        .with_constraint("demand", |decisions| {
            decisions[0] + decisions[1] >= 40.0  // Meet demand
        })
        .with_constraint("hydro_limited", |decisions, state| {
            decisions[0] <= state[0]  // Hydro limited by water
        })
        .with_state_transition(|decisions, state, noise| {
            // New level = old level - hydro + inflow
            state[0] - decisions[0]  // Inflow added in stage 2
        });

    // Stage 2: Similar structure with inflow
    // ... (similar to stage 1 but with inflow)

    // Stochastic inflow
    let mut process = StochasticProcess::new(1);
    process.add_stage(StageProcess {
        stage: 2,
        distributions: vec![
            DistributionType::Uniform { min: 20.0, max: 60.0 }
        ],
    }).unwrap();

    let saa = SAA::from_process(&process, 100, 42).unwrap();

    let config = Config::default();

    // Known solution (from DP)
    let solution = BenchmarkSolution {
        optimal_value: 50.0,  // Expected thermal cost (verify exact value)
        tolerance: 10.0,
        description: "Simple 2-stage hydro problem with stochastic inflow".to_string(),
        reference: Some("Pereira & Pinto (1991), Multi-stage stochastic programming".to_string()),
    };

    (system, config, saa, solution)
}
```

````markdown
# Benchmark Problems

This document describes the benchmark problems with known solutions used to validate the SDDP implementation.

## Newsvendor Problem

**Description**: Classic newsvendor problem - decide how much to buy before knowing demand.

**Formulation**:

- Stage 1: Buy x units at cost $10/unit
- Stage 2: Demand D ~ Uniform(0, 100) is realized
  - Sell min(x, D) at $20/unit
  - Salvage max(x - D, 0) at $5/unit
  - Shortage penalty $15/unit for max(D - x, 0)

**Known Solution**: Optimal value ≈ $425 (computed via dynamic programming)

**Tolerance**: ±$20 (due to sampling variance in SAA)

**Reference**: Classical newsvendor model, see Porteus (2002) "Foundations of Stochastic Inventory Theory"

**Test**: `test_newsvendor_benchmark_convergence()`

## Hydrothermal Problem

**Description**: Simple 2-stage hydro reservoir management problem.

**Formulation**:

- Initial reservoir: 50 units (max 100)
- Demand: 40 units per stage
- Stage 1: Choose hydro h1 (free) and thermal t1 ($10/unit)
  - h1 + t1 ≥ 40
  - h1 ≤ 50 (limited by water)
- Stage 2: Inflow I ~ Uniform(20, 60)
  - Reservoir level: 50 - h1 + I
  - Choose h2 and t2 to meet demand

**Known Solution**: Optimal value ≈ $50 (expected thermal cost)

**Tolerance**: ±$10

**Reference**: Based on Pereira & Pinto (1991) "Multi-stage stochastic optimization applied to energy planning"

**Test**: `test_hydro_benchmark_convergence()`
````
