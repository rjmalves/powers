## Technical Notes

### Implementation Approach

**Criterion Configuration**:

```rust
// benches/sddp_benchmarks.rs
use criterion::{criterion_group, criterion_main, Criterion, BenchmarkId};

fn forward_pass_benchmarks(c: &mut Criterion) {
    let mut group = c.benchmark_group("forward_pass");

    for num_stages in [1, 10, 100] {
        group.bench_with_input(
            BenchmarkId::from_parameter(num_stages),
            &num_stages,
            |b, &n| {
                let sddp = create_benchmark_problem(n);
                b.iter(|| sddp.forward_pass());
            },
        );
    }

    group.finish();
}

criterion_group!(benches, forward_pass_benchmarks, backward_pass_benchmarks);
criterion_main!(benches);
```

**Regression Detection**:

```bash
# Compare current to baseline
cargo bench --bench sddp_benchmarks --baseline main

# Check for regressions programmatically
python scripts/check_perf_regression.py \
    --baseline target/criterion/main/ \
    --current target/criterion/current/ \
    --threshold 5
```

### Edge Cases

1. **Noisy benchmarks**: Use median instead of mean, multiple samples
2. **Hardware variation**: Document reference hardware, allow tolerance
3. **Compiler version changes**: Expect some variation, document version
4. **Background processes**: Run benchmarks in isolated environment

### Performance Considerations

- **Benchmark overhead**: Keep benchmarks fast (<10s total) to avoid slowing CI
- **Sample size**: Balance accuracy vs speed (50-100 samples typically sufficient)
- **Warmup**: Include warmup iterations to stabilize JIT/cache effects
- **Measurement time**: Use criterion's adaptive measurement (10s default)

### Criterion Features

**Statistical Analysis**:

- Outlier detection and removal
- Confidence intervals (95%)
- Comparison to baseline with statistical significance
- Linear regression for trend detection

**Reporting**:

- HTML reports with plots
- Console output with colored diffs
- CSV export for custom analysis
- JSON export for programmatic access
