## Technical Notes

### Implementation Approach

**Feasibility Validator**:

```rust
pub struct PolicyValidator {
    system: System,
    constraints: Vec<Constraint>,
}

impl PolicyValidator {
    pub fn check_feasibility(&self, trajectories: &[Trajectory]) -> FeasibilityReport {
        let mut violations = Vec::new();
        for traj in trajectories {
            for stage in &traj.stages {
                // Check state bounds
                if stage.storage.iter().any(|&s| s < 0.0) {
                    violations.push(Violation::NegativeStorage { ... });
                }
                // Check action bounds
                if stage.generation.iter().any(|&g| g < 0.0) {
                    violations.push(Violation::NegativeGeneration { ... });
                }
                // Check constraints (power balance, water balance)
                if !self.check_power_balance(stage) {
                    violations.push(Violation::PowerBalance { ... });
                }
            }
        }
        FeasibilityReport { violations, all_feasible: violations.is_empty() }
    }
}
```

**Reasonableness Validator**:

```rust
pub struct ReasonablenessReport {
    pub unexpected_behaviors: Vec<UnexpectedBehavior>,
    pub is_reasonable: bool,
}

pub enum UnexpectedBehavior {
    SpillageWhenStorageLow { stage: usize, storage: f64, spillage: f64 },
    LowGenerationWhenLoadHigh { stage: usize, load: f64, generation: f64 },
    // ... other patterns
}
```

### Edge Cases

1. **Zero training iterations**: Should produce feasible but suboptimal policy
2. **Extreme scenarios**: Policy should remain feasible even with outliers
3. **Boundary conditions**: Storage at min/max, generation at limits
4. **Numerical precision**: Allow small tolerance for constraint violations (1e-6)

### Performance Considerations

- **Parallel validation**: Use `rayon` to validate trajectories in parallel
- **Early termination**: Stop checking trajectory after first violation (optional)
- **Caching**: Cache constraint evaluations to avoid recomputation
