## Context

Current input parsing accepts JSON but has **minimal validation**. Invalid inputs can cause panics, confusing errors, or silent failures. Production use requires robust validation with clear error messages.

**Current State**:

- Basic JSON parsing (serde_json)
- Minimal validation (negative values sometimes checked)
- Error messages often cryptic
- No validation of logical consistency (e.g., sum of probabilities = 1)

**Need**: Comprehensive input validation with actionable error messages.

---

## Acceptance Criteria

- [ ] **All Fields Validated**: Given any input field, when validating, then bounds, types, and logical constraints are checked
- [ ] **Clear Error Messages**: Given invalid input, when parsing fails, then error message identifies field, constraint, and correction
- [ ] **Early Failure**: Given invalid input, when parsing, then validation fails before computation starts
- [ ] **Examples Provided**: Given common errors, when reading docs, then examples show how to fix
