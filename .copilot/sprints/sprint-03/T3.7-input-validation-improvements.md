## Context

**Original Scope**: Input validation improvements (6 hours)

**Expanded Scope**: Factory API + Input Validation (10 hours)

### Problem Statement

Current SDDP construction has a **testing/benchmarking gap**:

1. **Low-level API** (`SddpAlgorithm::new()`): Powerful but requires ~50 lines of boilerplate
2. **Builder API** (`SddpBuilder`): Limited to explicit scenarios, doesn't support distribution-based uncertainty (production use case)
3. **Missing**: Production-ready factory method for JSON-based construction
4. **Validation Gap**: Minimal input validation, cryptic error messages

### Why This Matters

- **T3.6 Blocker**: `parallel_efficiency.rs` benchmark needs simple construction API
- **Test Maintenance**: Every integration test duplicates 50+ lines of construction boilerplate
- **Production Readiness**: Invalid inputs cause panics or silent failures
- **Developer Experience**: No single-line way to create SDDP from files

### Solution Overview

Create **three-tier API architecture**:

1. **Factory API** (NEW): `SddpAlgorithm::from_files()` → Tests, Benchmarks
2. **Builder API** (EXISTING): `SddpBuilder` → Simple Unit Tests
3. **Low-Level API** (EXISTING): `SddpAlgorithm::new()` → Power Users

The factory method provides a natural checkpoint for comprehensive validation.

**Reference**: See `docs/ARCHITECTURE-SDDP-CONSTRUCTION-API.md` for full architectural analysis.

#### Validation Rules: Config

- [ ] **Config validation** (`validate_config()`):
  - `num_iterations > 0`: "num_iterations must be positive (got {value})"
  - `num_forward_passes > 0`: "num_forward_passes must be positive (got {value})"
  - `num_simulation_scenarios > 0`: "num_simulation_scenarios must be positive (got {value})"
  - `seed` is valid: No constraints (any u64 is valid)
  - `output_path` if provided: Path is writable (warning, not error)

#### Validation Rules: System

- [ ] **System validation** (`validate_system()`):
  - **ID ranges**: All IDs are 0..N-1 (no gaps, no duplicates)
  - **Bus validation**:
    - `deficit_cost >= 0`: "Bus {id} deficit_cost must be non-negative"
  - **Line validation**:
    - `source_bus_id` and `target_bus_id` exist
    - `direct_capacity >= 0` and `reverse_capacity >= 0`
    - `exchange_penalty >= 0`
  - **Thermal validation**:
    - `bus_id` exists
    - `cost >= 0`
    - `0 <= min_generation <= max_generation`
  - **Hydro validation**:
    - `bus_id` exists
    - `downstream_hydro_id` exists (if provided)
    - `productivity > 0`
    - `0 <= min_storage <= max_storage`
    - `0 <= min_turbined_flow <= max_turbined_flow`
    - `spillage_penalty >= 0`
    - No cycles in hydro cascade

#### Validation Rules: Graph

- [ ] **Graph validation** (`validate_graph()`):
  - **Node IDs**: Unique, form valid sequence
  - **Stage IDs**: Sequential from 0 (no gaps)
  - **Season IDs**: Valid range
  - **Dates**: `start_date < end_date` for each node
  - **Risk measure**: One of ["expectation", "cvar", "worstcase"]
  - **Stochastic processes**: Valid process names
  - **Edge validation**:
    - `source_id` and `target_id` exist
    - `0 < probability <= 1`
    - `discount_rate >= 0`
  - **Probability consistency**: Per source node, outgoing edge probabilities sum to 1.0 (±1e-6)
  - **Graph connectivity**: All nodes reachable from root

#### Validation Rules: Recourse

- [ ] **Recourse validation** (`validate_recourse()`):
  - **Initial storage**: Length matches number of hydros
  - **Initial storage values**: Within hydro storage bounds
  - **SAA scenario counts**: Match graph structure
  - **Distribution parameters**: Valid for Normal/LogNormal (mean > 0, std_dev > 0)

#### Validation Rules: Consistency

- [ ] **Cross-validation** (`validate_consistency()`):
  - Graph references valid system elements
  - Recourse references valid hydros
  - Number of stages in graph matches recourse expectations

## Technical Notes

### Design Decisions

1. **`SddpInstance` wrapper**: Encapsulates algorithm + config + SAA

   - Rationale: Enables zero-argument `train()` and `simulate()`
   - Trade-off: Extra type, but cleaner API
   - Alternative considered: Direct `SddpAlgorithm` with setters (rejected - pollutes core type)

2. **Validation placement**: Inside `Input::from_paths()`

   - Rationale: Single checkpoint, early failure
   - Overhead: <10μs for typical inputs (~0.002% of training time)
   - Trade-off: Can't skip validation (acceptable - validation is cheap)

3. **Error type**: Use `String` initially

   - Rationale: Simple, flexible, easy to compose error messages
   - Future: Can refine to structured enum in T3.8 if needed
   - Trade-off: Less type safety, but more readable errors

4. **Backward compatibility**: Keep all existing APIs
   - `Input::build()` still works (calls `from_paths()` internally)
   - `SddpAlgorithm::new()` unchanged
   - `SddpBuilder` unchanged
   - New code recommended to use factory, old code unaffected

### Performance Considerations

- **Factory overhead**: Zero (factory pattern, not abstraction)
- **Validation overhead**: <10μs (<0.002% of training time)
- **Memory overhead**: ~208 bytes for `SddpInstance` wrapper (~0.02% of typical problem)
- **All benchmarked**: Must verify <1% overhead in tests

### Implementation Order

### Edge Cases to Handle

- **Missing files**: Clear error with file path
- **Malformed JSON**: Preserve serde_json error, add context
- **Circular dependencies**: Detect in hydro cascade validation
- **Disconnected graph**: Detect in graph connectivity validation
- **Floating point edge cases**: Probability sums with tolerance (±1e-6)
- **Platform differences**: Path handling (Windows vs Unix)

## Migration Guide for Existing Code

### Before (Manual Construction - 50+ lines)

```rust
let input = Input::build(&input_args.path);
let config = &input.config;
let recourse = &input.recourse;
let graph_input = &input.graph;
let seed = config.seed;

let node_data_graph = graph_input.build_sddp_graph(&input.system)?;
let initial_condition = recourse.build_sddp_initial_condition();
let saa = recourse.generate_sddp_noises(&node_data_graph, seed);

let mut sddp_algo = sddp::SddpAlgorithm::new(
    node_data_graph,
    initial_condition,
    seed
).unwrap();

let _training_result = sddp_algo.train(
    config.num_iterations,
    config.num_forward_passes,
    &saa,
)?;

let simulation_handlers = sddp_algo.simulate(
    config.num_simulation_scenarios,
    &saa
)?;
```

### After (Factory API - 5 lines)

```rust
let mut sddp = SddpAlgorithm::from_files(
    "example/config.json",
    "example/system.json",
    "example/graph.json",
    "example/recourse.json",
)?;

let training_result = sddp.train()?;
let simulation_handlers = sddp.simulate()?;
```

**Reduction**: 80% less boilerplate, same functionality, same performance.
