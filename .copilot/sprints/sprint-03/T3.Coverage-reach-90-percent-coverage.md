**sddp/mod.rs** (89% → 93% target, +4%):

- **Focus areas**:

  - Convergence edge cases
  - Parallel execution error handling
- **Estimated**: 15 tests to cover 15 lines

### Testing Strategy

1. **Identify uncovered lines**: Use `cargo tarpaulin --ignore-tests` and examine output
2. **Categorize gaps**: Error paths, edge cases, or rare branches
3. **Write targeted tests**: One test per uncovered scenario
4. **Verify coverage increase**: Re-run tarpaulin after each batch

### Implementation Approach

```rust
// Example: Test solver error handling
#[test]
fn test_solver_infeasible_problem() {
    let mut solver = Solver::new();

    // Create infeasible problem: x >= 10 AND x <= 5
    solver.add_variable("x", 10.0, f64::INFINITY);
    solver.add_constraint("c1", vec![("x", 1.0)], -f64::INFINITY, 5.0);

    let result = solver.solve();
    assert!(result.is_err());
    assert_eq!(result.unwrap_err().kind(), ErrorKind::Infeasible);
}
```

### Edge Cases

1. **Uncoverable lines**: Dead code, defensive assertions (mark with `#[cfg(not(tarpaulin_include))]`)
2. **Platform-specific code**: May not be testable on all platforms
3. **Unsafe code**: Difficult to test without triggering undefined behavior
4. **Panic paths**: Use `#[should_panic]` tests

### Performance Considerations

- **Test execution time**: New tests should be fast (<100ms each)
- **CI impact**: +35 tests should add <5s to CI time
- **Coverage measurement**: Tarpaulin adds ~20% overhead
