# T3.9: Error Message Improvements

**Sprint**: 3  
**Estimated Effort**: 4 hours  
**Priority**: MEDIUM (Priority 3 - Input/Output Improvements)  
**Status**: NOT STARTED

---

## Context

Current error messages are often **cryptic** or **generic**. Production users need clear, actionable error messages that help them fix issues quickly.

**Current State**:

- Generic errors: "Invalid input", "Solver failed"
- No context: Missing line numbers, field names
- No guidance: Errors don't suggest fixes
- Stack traces exposed to users

**Need**: User-friendly error messages with context and actionable guidance.

---

## Acceptance Criteria

- [ ] **Context Included**: Given any error, when displayed, then relevant context (field name, line number, value) is shown
- [ ] **Guidance Provided**: Given common errors, when displayed, then suggestion for fix is included
- [ ] **No Stack Traces**: Given user-facing errors, when displayed, then stack traces are hidden (unless debug mode)
- [ ] **Error Categories**: Given different error types, when handling, then appropriate error type is used (validation, solver, file I/O)

---

## Tasks

### Implementation

- [ ] **Create error hierarchy** (`src/error.rs`): ValidationError, SolverError, IOError, etc.
- [ ] **Add context to errors**: Use `thiserror` or `anyhow` for context
- [ ] **Implement Display for errors**: User-friendly messages
- [ ] **Add error suggestions**: Common fixes for common errors

### Testing

- [ ] **Error message tests** (20 tests): Verify error clarity and context
- [ ] **Error type tests** (10 tests): Verify correct error type used

### Documentation

- [ ] **Document error types** (`src/error.rs` doc comments)
- [ ] **Create troubleshooting guide** (README or TESTING.md section)
- [ ] **Add common errors section**: With examples and fixes
- [ ] **Update CHANGELOG.md**
