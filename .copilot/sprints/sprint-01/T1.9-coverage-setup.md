# T1.9: Code coverage measurement setup

**Sprint**: 1  
**Estimate**: 3 hours  
**Priority**: Medium  
**Type**: Infrastructure  
**Dependencies**: T1.1-T1.8 (all tests and CI)

## Description

Set up code coverage measurement and reporting to track which parts of the codebase are tested. Integrate coverage into CI and establish coverage targets. This provides visibility into testing completeness and identifies untested code.

## Context

Code coverage metrics help:

- Identify untested code paths
- Track testing progress over time
- Enforce minimum coverage thresholds
- Guide test prioritization

We'll use `cargo-tarpaulin` for coverage measurement and integrate with CI.

## Technical Notes

### Installation and Setup

```bash
# Install tarpaulin
cargo install cargo-tarpaulin

# Run coverage locally
cargo tarpaulin --out Html --output-dir coverage

# Open report
open coverage/index.html
```

### Configuration File: `tarpaulin.toml`

```toml
[configuration]
output-dir = "coverage"
run-types = ["Tests"]
exclude-files = [
    "target/*",
    "tests/*",
]

[report]
out = ["Html", "Lcov"]
```

### GitHub Actions Integration

Add to `.github/workflows/test.yml`:

```yaml
coverage:
  name: Code Coverage
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@v4

    - name: Install Rust
      uses: actions-rs/toolchain@v1
      with:
        profile: minimal
        toolchain: stable
        override: true

    - name: Install tarpaulin
      run: cargo install cargo-tarpaulin

    - name: Install system dependencies
      run: |
        sudo apt-get update
        sudo apt-get install -y cmake build-essential

    - name: Run coverage
      run: cargo tarpaulin --out Lcov --output-dir coverage

    - name: Upload to Codecov (optional)
      uses: codecov/codecov-action@v3
      with:
        files: ./coverage/lcov.info
        fail_ci_if_error: false
```

### Interpreting Coverage

**Good Coverage**:

- All critical paths tested
- Edge cases covered
- Error handling tested

**Coverage Doesn't Mean**:

- Code is correct (can have bugs with 100% coverage)
- Tests are good quality
- All scenarios tested

**Focus**: Coverage is a guide, not a goal. Quality tests > high coverage.
