### Key Points to Emphasize

1. **Test Quality > Quantity**: A few good tests beat many poor tests
2. **Test What Matters**: Focus on algorithm correctness and numerical stability
3. **Tests as Documentation**: Tests show how code should be used
4. **Maintain Tests**: Keep tests passing, update when code changes

### Examples to Include

1. **Good Test Example**:

```rust
/// Tests that BendersCut correctly evaluates intercept at reference state.
///
/// The intercept at the reference state should equal the base intercept,
/// as the coefficient term becomes zero.
#[test]
fn test_cut_intercept_at_reference_state() {
    // Arrange
    let reference_state = vec![100.0, 200.0];
    let coefficients = vec![1.5, -0.5];
    let base_intercept = 42.0;
    let cut = BendersCut::new(
        reference_state.clone(),
        coefficients,
        base_intercept
    ).unwrap();

    // Act
    let intercept = cut.intercept_at(&reference_state);

    // Assert
    assert_float_approx_eq!(intercept, base_intercept, 1e-10);
}
```

2. **What to Avoid**:

```rust
// BAD: Unclear what is being tested
#[test]
fn test_cut() {
    let c = BendersCut::new(vec![1.0], vec![2.0], 3.0).unwrap();
    assert_eq!(c.intercept_at(&vec![1.0]), 3.0);
}

// BAD: Testing too many things
#[test]
fn test_everything() {
    // ... 50 lines of tests ...
}

// BAD: Flaky due to randomness
#[test]
fn test_random_thing() {
    let x = random(); // No fixed seed!
    assert!(x > 0.5); // Will fail sometimes
}
```
