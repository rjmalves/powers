## Technical Notes

### Module Documentation Best Practices

**Good Module Docs Include**:
1. **One-line summary**: What this module does
2. **Brief explanation**: Key concepts (2-4 sentences)
3. **Key features**: Bullet list of notable capabilities
4. **Usage guidance**: Link to examples or guides
5. **References**: Links to detailed documentation

**Module Docs Should NOT Include**:
- Lists of public items (rustdoc auto-generates)
- Detailed API documentation (belongs on items)
- Extensive implementation details (belongs in architecture docs)
- Long usage examples (belongs in docs/guides/ or item examples)

### Example: Good vs Redundant

**❌ Redundant (auto-generated by rustdoc)**:
```rust
//! This module contains:
//! - `SddpAlgorithm`: The main algorithm struct
//! - `ForwardPass`: Performs forward simulation
//! - `BackwardPass`: Performs backward cut computation
//! - `CutPool`: Manages Benders cuts
//! - `train()`: Trains the policy
```

**✅ Essential**:
```rust
//! Implements SDDP algorithm for multistage stochastic optimization.
//! Supports parallel execution, cut management, and risk measures.
```
